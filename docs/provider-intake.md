# 空き情報・利用申込み受付

事業所詳細 `/directory/[id]` と、連携先 `/facility/[id]` に空き情報の案内と申込み導線を表示する。管理は Cares `/manage`、受付詳細は `/manage/applications/[id]`。

## 対象・受信者

- `is_owner_verified=true` かつ有効な受付担当者がいる事業所を対象とする。初期状態は受付有効。担当者は一時停止できる。
- 受付担当者は、レビュー記録のある承認済み `cares_owner_claims.user_id`、または連携事業所に割当済み・同一法人・有効な OS `admin/manager`。一般職員、他法人の割当、未承認の申請者には公開しない。
- Cares単独オーナーにOS契約・OSプロフィールは要求しない。未承認の事業所への送信は受け付けない。受信権限は毎回判定する。
- 所有申請の直接INSERTは禁止。既存の申請APIは service role で `pending` を登録する。承認は信頼された管理者の処理で行う。

## 空き情報

公開中のOSプロフィールの空き状況を優先し、Cares単独の場合は事業所の登録値を使用。Cares受付画面で保存すると、掲載データと連携OSプロフィールを同時に更新する。後からOSの投稿で更新した状態も反映される。曜日・送迎・見学などの案内文は1000文字まで。案内文の更新日と、受入れ・日程は事業所との確認が必要である旨を表示する。

## 申込み

- ログイン不要。見学・体験利用・利用相談を選ぶ。必須は申込者名・利用希望者名・電話またはメール。
- 手入力のみで完結できる。添付は1人分・3件まで、1件3MiB以下のJPEG/PNG/WebP/PDF。
- AIは任意・個別同意制。画像と5ページ以内のPDFに対応。OpenAI Responses API `gpt-4.1-mini`（`CARES_INTAKE_AI_MODEL`で変更可）、`store:false`、厳格なJSON出力。資料中の命令には従わず、記載事項だけを転記する。
- AI結果は即時入力しない。確認後に反映し、申込者の連絡先は自動補完しない。複数利用者・不明情報を推測しない。AI失敗時も添付と手入力は利用可能。
- 確認画面で宛先・項目・添付一覧を確認し、健康・介護情報と原本の提供への同意を得て送信する。受付日時と同意文面のバージョンを記録。
- 受付後はCares内通知を担当者へ発行。通知本文に利用者名・介護情報を含めない。メール/SMS自動送信は含まない。
- 受付詳細で原本ダウンロード・CSV保存・状況更新が可能。状況更新は申込者に自動連絡しない。利用契約・日程確定・OS利用者台帳への自動登録は行わない。

## データ保護・再送

機密テーブルはRLSを有効にし、anon/authenticatedには権限・ポリシーを付与しない。service role経由のサーバーAPIだけが扱う。添付バケット `cares-applications` は非公開。原本はアクセスの都度担当者権限を確認し、添付として返す。署名URLを公開画面に埋め込まない。

匿名下書きはランダムなHttpOnly/SameSite cookieとHMAC照合、24時間有効。タブ間の下書き混同を防ぎ、確認した添付IDとDB上の全添付の一致を送信時に確認する。提出は下書き行をロックし、受付記録・通知を一つのトランザクションで作成。同一下書きの再送は同じ受付番号を返す。アップロード中・削除中の資料を送信しない。

APIは同一Origin・本文サイズ・ファイル内容の形式を検証。IPはHMAC化して回数制限に使い、個人情報・ファイル名・AI応答をログに書かない。AIは下書き5回/日・IP15回/日・全体200回/日を上限とする。ブラウザの永続ストレージへ申込内容を保存しない。

## 保持期間・設定

- 未送信の資料：下書き24時間で失効、日次削除により原則48時間以内。
- 送信済み申込み・添付：180日経過後の日次削除。該当する受付通知も削除する。
- Vercel Cron `/api/intake/cleanup` を毎日03:00 JSTに実行。`CRON_SECRET`を照合。Storage削除成功後にDBを削除し、失敗は503にして再実行可能とする。100件単位で処理し、時間・件数上限に達したときは未処理ありを503で返す。
- 環境変数：既存Supabase設定、`OPENAI_API_KEY`、`CRON_SECRET`。キーはサーバー専用。AIキーが未設定なら手入力受付は引き続き使える。

## 検証

`npm test`、`npm run typecheck`、`npm run lint`、`npm run build`。`tests/intake.test.cjs` は実PostgresエンジンのPGliteで権限・組織境界・Cares単独所有・再送・添付整合性・保持期間を確認する。ブラウザ検証・AI実接続は架空データのみを使用し、本番事業所へ試験の申込みや通知を送らない。
